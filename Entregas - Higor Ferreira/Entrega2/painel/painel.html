Como funciona

O pipeline em sete movimentos

A ordem importa: cada etapa só faz sentido depois que a anterior respondeu à sua pergunta. As duas em destaque são as que separam este projeto de uma demonstração de detecção.

01

Entender o YOLO26

Cabeça one-to-one sem NMS, sem DFL, com STAL e ProgLoss. Isso muda o código: augment=True deixa de existir.

02

Ler o dado cru

Abrir cada imagem e cada arquivo de rótulo. É essa leitura que revela vários protocolos de aquisição misturados no mesmo split.

03

Particionar por protocolo

Todo o protocolo 192×256 fica fora do treino. Holdout de protocolo, não holdout aleatório.

04

Sintetizar lesões

Copy-paste com máscara do encéfalo, harmonização de intensidade e blending de Poisson. O rótulo é conhecido, não estimado.

05

Treinar sob orçamento

O argumento time= sobrescreve epochs: as épocas viram saída do experimento e o relógio fica fixo.

06

Diagnosticar o modelo

Calibração, limiar operacional justificado, taxonomia de erros, domain shift, robustez e alarme falso fora do domínio.

07

Entregar o laudo

Tensor vira JSON versionado, e JSON vira uma interface Flask que alguém usa sem abrir o notebook.

Honestidade

O que este projeto não prova

A parte mais importante de um relatório técnico é a lista do que ele não sustenta.

  1. Não é diagnóstico. As classes são convenção de anotação de um conjunto público, sem laudo clínico verificado. O sistema aprende a convenção, não a doença.
  2. A partição externa é um proxy. Geometria de aquisição sugere fonte diferente, mas não prova. A afirmação defensável é «há deslocamento mensurável entre esses subconjuntos».
  3. O sintético herda o viés do original. As lesões vêm do mesmo banco de 745 recortes: ampliam variedade de posição e escala, não criam patologia nova.
  4. Os artefatos são simulados. Reproduzem o modelo físico, não a distribuição empírica de um equipamento real.
  5. Estabilidade não é probabilidade. É concordância entre três vistas da mesma imagem; um modelo consistentemente errado exibe estabilidade alta.
  6. O orçamento limita o resultado. Com quinze minutos de treino, o número reportado é um piso, não o teto do modelo.
  7. Não há escala física. Sem o campo PixelSpacing do DICOM, nenhuma medida é reportada em milímetros.
